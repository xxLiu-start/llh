# SkillBank train/test split

Training uses `train_dataset/terminal-bench-pro`. Testing uses the original Terminal-Bench 2.1 task directory, `eval/TB-harness/datasets/terminal-bench-2-1/tasks`. The new test config loads the learned bank with updates disabled.

Training uses Chinese Manager/Executor/Auditor, Router, and Skill-learning prompts (`prompt_language: zh`) and generates Chinese Skill content (`content_language: zh`). Terminal-Bench 2.1 evaluation keeps English role and Router prompts (`prompt_language: en`) with learning disabled; its Router can still select and inject the Chinese Skills. Task instructions stay in their source language. The original Terminal-Bench 2.1 tasks are absent from this checkout, so their instruction language cannot be confirmed here.
Each Skill stores a short `routing_summary` describing its capability, applicability, and key exclusions. Router candidate cards contain that summary and selection metadata; after ID/version validation, only the selected Skill's view for the current role (`input_use`, `output_spec`, `guidance`, `avoid`) is injected. Older SkillBank entries receive a bounded summary in memory, and the exact former built-in Router prompts are upgraded in memory without changing custom prompts.
Both configurations use `deepseek-v4.1-flash`. Claude Code sends Anthropic Messages to a local request proxy; for these workflows, the proxy translates text and tool messages to OpenAI Chat Completions at `/v1/chat/completions` and converts structured function calls back into Anthropic `tool_use` blocks. This uses the gateway protocol that returned structured tool calls in the endpoint check. The driver and test script normalize trailing `/v1` before Harbor applies its scoped environment, and the proxy forwards the configured key as `Authorization: Bearer`.

Use the existing Terminal-Bench 2.1 Conda environment, Docker, and an Anthropic-compatible model endpoint:

```bash
export ANTHROPIC_API_KEY=...
export ANTHROPIC_BASE_URL=...
python training/check_model_endpoint.py
./training/run_terminal_bench_pro.sh --dry-run
./training/run_terminal_bench_pro.sh --task maze-shortest-path-solver
./training/run_terminal_bench_pro.sh --start-from analyze-arm-shellcode-network-connections
./training/run_terminal_bench_pro.sh
./training/run_terminal_bench21_test.sh
```

For an explicit evaluation with both the regular and temporary SkillBanks, run `./training/run_dual_skillbank_eval.sh`. It disables learning, runs each selected task once, snapshots both source bank files into `output/dual-skillbank-eval/state/`, and writes per-task correctness, reward, token usage, and selected Skill names to `results/per_task.csv`. Repeated runs in that output directory reuse the same frozen bank; choose a new `--output` to evaluate newer Skill versions. The default dataset is the original TB2.1 test set, which must be installed before running. You can pass `--dataset train_dataset/terminal-bench-pro --output output/pro-dual-skillbank-eval` for an in-sample check.

If task containers cannot reach `downloads.claude.ai`, place the matching executable at `output/<dataset-name>/jobs/claude_code_cache/<version>/claude` or set `LH_CLAUDE_OFFLINE_BINARY` to its absolute path. Training and original LHH evaluation check matching caches in other output directories and under `output/his/`, verify `claude --version`, and mount the binary to avoid Harbor's online installer. Original evaluation reports a missing cache before starting the first task.

The trainer runs tasks in sorted order. It extracts trajectory experience, then an Evolution Planner can request multiple independent Skill creations, revisions and Router repairs. Each Builder must return the exact Skill schema; one structural correction uses only its draft and plan when needed. After Harbor agrees with the Harness outcome, valid provisional candidates are copied from the disposable trial SkillBank to the persistent training bank. They can be routed in later training tasks. A shared source-task replay is combination-level evidence and never independently validates each candidate. Promotion requires independent validation. The previous validated version remains in the regular bank while a revision is provisional. Use `--task` repeatedly to select tasks and `--force` to rerun prior decisions.

The default training template allows up to 25 rounds, 200 Executor model turns per episode, and 4200 seconds per role episode. Manager and Auditor have separate 200-turn limits. The per-response output limit remains 65536 tokens. Role history and verified context are capped at 30000 and 20000 characters. Each baseline or candidate trial checks a soft 1.5 million token limit between completed rounds; reaching it records `token_budget_exhausted` while still allowing failure diagnosis. This is not a precise billing cap: one round can overshoot it, and diagnosis and Builder calls add usage. These settings may lower the completion rate for difficult tasks. To allow longer runs, copy `terminal_bench_pro_skill_learning.yaml`, adjust the limits, and pass `--template PATH`. `skill_token_budget` only limits injected Skill text, and `skill_reward_reference_tokens` is a reward scale. Completed model requests in timed-out episodes are now included in reported usage when proxy traces are available. An in-flight request can still be missing, and independent candidate validation may run the task a second time.

The training Manager receives the original task, current state, task contract, short per-round audit findings, and recent Harness feedback. Executor and Auditor receive the current subtask and explicitly referenced audit evidence. Post-task learning first extracts positive and negative experiences from a bounded excerpt of every recorded round. The second-stage SkillBank/Router assessment receives those experiences, a short round index, and up to six detailed evidence excerpts; Builder receives up to eight excerpts, prioritizing cited rounds. The extracted experiences and any extraction error are retained in skill_learning. Complete reports, model I/O, and raw trajectories remain in run logs and view-only provenance; raw tool transcripts are not replayed in learning prompts. Experience extraction adds a model call for tasks with recorded rounds. Claude Code still manages conversation history within a single role episode when it makes successive tool calls.

Changed Skill revisions receive a separate model review before staging. It checks that reusable guidance survives and task-specific details are generalized. In Evolution Planner runs, each review result is recorded in that request's `request_outcomes`, and a failed review rejects that request. The older batch flow records findings in `skill_learning.revision_preservation_reviews` and rejects its batch on failure. This content review does not replace independent validation.

The Evolution Planner writes candidates and per-request outcomes to the run's `skill_candidate.json` artifact and provenance records. The older replay flow also saves a readable copy at `output/<dataset-name>/skill_tmp/<task>/<run-id>/candidate.json`; its `validation.json` records the shared replay result and reward difference. These owner-readable copies are for inspection only: training never reads them, and a write failure does not change the result. The batch replay config is stored under `generated_configs/`.

The `./training/run_terminal_bench_pro.sh` wrapper streams stdout and stderr to a unique `output/<dataset-name>/console_logs/train-*.log` file and prints its path. Directly invoking the Python module does not create this console log.

Terminal-Bench Pro verifier scripts download `uv 0.7.13` from GitHub on every run. Original LHH evaluation, Skill training, and dual SkillBank evaluation now mount a matching local binary into the verifier phase and skip that redundant download for tasks using the pinned installer. The benchmark's `tests/test.sh`, test cases, Dockerfile, and agent PATH remain unchanged. The host must have an executable `uv 0.7.13`; set `LH_VERIFIER_UV_BINARY=/absolute/path/to/uv` if it is not on PATH. A missing or wrong version fails before the Harbor trial starts. Existing zero-score records are unchanged; rerun affected tasks with `--force`.

## View-only provenance

Each task has one append-only JSONL file at `output/<dataset-name>/provenance/<task>.jsonl`; the exact path is printed when the task starts. Reruns append to the same file, and every record carries its `run_id` so runs remain distinguishable. This file is never read by the trainer or used for Skill selection or acceptance. Docker preflight records live at `output/<dataset-name>/docker_preflight/`, while Harbor task jobs remain at `output/<dataset-name>/jobs/`.

Records include the complete model requests and responses for every role and Skill-learning call, with one `trace_id` tying client and upstream sides of a call together. Bridge runs save the incoming Anthropic request, translated OpenAI request, OpenAI response, and translated Anthropic response. JSON and SSE bodies are saved as structured data alongside their original text; authentication headers are excluded. Individual call records also remain in each Harbor episode's `model_io.jsonl`.

Claude Code can emit the same final answer in both an `assistant` event and a `result` event. The adapter uses the final `result` as `assistant_visible_output`, with the last assistant text as a fallback. Raw event logs still retain both protocol events for inspection.

The same task-run file includes active and historical Skill versions, current and historical Router Prompt versions, the generated and assessed candidate, static prompt templates in the run's language with SHA-256 version IDs, baseline/candidate reports, trial failures, and the final decision. SkillBank snapshots before training, after each trial, and after commit make changes traceable across runs. The files are created with owner-only permissions because full prompts and responses may contain task data. Runs completed before this feature cannot be retroactively given exact model request/response bodies.

Harbor runs use an unattended Manager policy: resolve ordinary ambiguity from task instructions, metadata, environment files, and audited evidence; report a task-definition blocker when those sources are insufficient. If the model still requests `Next: ask` and rounds remain, it gets one evidence-based replan. A repeated request or exhausted budget records `unattended_needs_human_input` and the question. Interactive runs retain the human gate. Failed tasks with analyzable role output attempt failure diagnosis regardless of abort reason. The `skill_learning` report distinguishes a genuine model action from a skipped diagnosis or model/builder error and retains the reason, error stage, and raw unparsable output.

To rerun the poker task, use `./training/run_terminal_bench_pro.sh --task advanced-poker-hand-classifier --force`. Without `--force`, a nonfailed prior decision is returned with `execution: reused_prior_decision`; no model call occurs. A forced run starts the task afresh and may then diagnose and validate a candidate. `--validation-replay` restores the default validation behavior; changing this switch also starts a fresh task run rather than reusing a decision from the other mode. Turning validation on later does not retroactively validate an earlier candidate. Each run gets a distinct ID, Harbor job, config, bank snapshot, and `decisions/attempts/<task>/<run-id>.json`. The latest decision remains at `decisions/<task>.json`; its previous contents are archived under `decisions/history/<task>/` before replacement. Infrastructure failures are recorded in the attempt file without replacing the latest decision. There is currently no diagnostics-only replay of an old trajectory. Extraction normalizes the observed negative-experience `strategy` alias while preserving the raw output. Recorded artifact paths are separated from round citations; unverified paths are excluded from the Builder. If the Harbor verifier disagrees with the Harness completion decision, the baseline proposal is quarantined and recorded as `learning_outcome_mismatch`. Candidate acceptance and Skill success counters prefer Harbor correctness while retaining the Harness outcome and hard-constraint checks.

Each actual model input also has a `runtime_prompt_version` record with the system message, conversation messages, and tool definitions. Its `trace_id` links to the corresponding `model_io` request and response; `previous_version_id` links prompt revisions within the same phase, role, and episode. Skill snapshots and candidates have content hashes, and a revised candidate points to its prior Skill hash. Trace write failures only produce warnings and do not affect training decisions.

The Terminal-Bench 2.1 test tasks are not present in this checkout. Prepare them as described in `eval/TB-harness/README.md` before testing. Model runs have not been launched here.

The endpoint check makes one small request to each of `/v1/chat/completions` and `/v1/messages` using the same Bearer key, and prints only HTTP status codes. If the proxy still fails, its `request_proxy_requests.jsonl` records a `forwarded_auth` event with boolean `bearer` and `x_api_key` fields, without recording the key.
If both checks fail with `ConnectionRefusedError`, run `python training/check_model_endpoint.py --direct` to bypass a configured HTTP(S) proxy and distinguish a broken local proxy from an API response.
Run `python training/check_model_endpoint.py --direct --tools` to check whether each protocol honors a forced structured tool call. A plain-text imitation of a tool call cannot be executed by Claude Code and is treated as a provider protocol failure rather than a completed training decision. The bridge currently supports text messages and client tool calls; unsupported content blocks fail explicitly.
For DeepSeek thinking-mode tool continuations, the bridge keeps `reasoning_content` in memory for the life of each role episode and restores it to later OpenAI requests. It does not write that content to the proxy audit log.
